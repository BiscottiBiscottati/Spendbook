Export
One versioned JSON file for a bug report: this chat’s records, its measurement runs, the counters for the rows the retention cap folded, and the all-time totals. It carries no chat identifier, no prompt text and no request body. Off by default. When you turn it on, the character or group name of the open chat is added to the file and to the download’s name; a chat file name is never included.
Import from VectFox
Brings this chat’s VectFox usage into Spendbook: its records, its measurement runs and the counters for the rows the retention cap folded, translated to Spendbook’s origins. The old data is left exactly as it is, so switching back to VectFox still finds it. A second click adds nothing.
Price table
Prices are per million tokens and are used only for a provider and model you enter here. A cost or cache discount the provider reports is shown as reported and never recomputed, and OpenRouter credits are not converted. Cost is resolved from this table for every row, including rows the retention cap folded. The all-time line counts tokens across chats; cost is per chat.

How to read these numbers

  • Measured: the provider reported the number on the response. This is what you were billed for, and a cost or cache discount the provider sent is shown as reported.
  • Estimated: the provider reported no usage, so the prompt is counted with SillyTavern's tokenizer and marked with a tilde. It is a close count, not a bill, and a cache hit is never estimated.
  • Unavailable: neither the provider nor the tokenizer produced the number. It is shown as — and never as 0, so a request that reported nothing cannot look free.
  • The hit rate is token-weighted: cached prompt tokens over the prompt tokens the provider reported for those same requests, never an average of per-request percentages. A request without both counts is left out of the ratio rather than counted as a miss.
  • Shared prefix: how many estimated tokens this request shared, from the start, with the previous comparable request — the same provider, model and origin, so a quiet or internal call in between cannot move the story baseline. The provider never reports this count; it is counted with SillyTavern's tokenizer and marked with a tilde, and a request with no comparable predecessor shows —.
  • Possible prefix breaker: the request shared at least 2,048 of those estimated tokens with its comparable predecessor yet reported zero cached tokens. Something before the cache boundary changed the prompt, or the provider dropped the cache; it is a suspicion, not a measurement of the cause. A request that reported no cache count at all is never flagged, and neither is a failed or stopped one.
  • Configuration: the label a host extension set for the requests it drove, read when each request was sent, so a label set before a run covers that run and never relabels a row already recorded. It is never saved as a setting; a request with no label is shown and compared as default.
  • Coverage: the share of prompt tokens the provider actually reported. An estimated prompt counts as uncovered, so a provider that omits usage lowers coverage instead of disappearing from it. A completed request that reported no prompt count at all caps coverage at the share of requests that did report one, because its prompt has a size nobody measured. Failed and stopped requests are in no denominator.
